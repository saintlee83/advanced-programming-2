# Kitty ver — 발표 스크립트

대상: [seoul-population-kitty](seoul-population-kitty/) · [문서 목록](README.md) · [코드 해설](kitty-ver.md)

개발을 전혀 몰라도 이 문서만 읽고 **발표하고, “이 기능은 어떻게 구현했어요?”에 답할 수 있게** 만든 대본이다.
기준은 2026-09-19의 코드다(PyQt5, 애니메이션 없음, 화면은 ‘데이터 불러오기 → 차트 보기’ 두 단계, 차트 11개, 주요 지표는 비교표).

## 0. 이 문서 쓰는 법

- **「따옴표 상자」는 그대로 읽으면 되는 대본**이다. 외우지 말고 뜻만 이해한 뒤 자기 말투로 바꿔도 된다.
- 질문별 답변은 세 단계로 되어 있다. 대부분의 질문은 1단계에서 끝난다.
  1. **한 줄 답** — 먼저 이것만 말한다.
  2. **풀어서 말하기** — “조금 더 자세히요?”라고 하면 읽는다.
  3. **더 물어보면** — 코드까지 묻는 경우에만 쓴다. **코드 위치**를 열어 보여 주면 된다.
- 코드 위치는 `파일 › 함수 이름`으로 적었다. 편집기에서 함수 이름으로 검색(Ctrl/Cmd+F)하면 바로 찾는다. 줄 번호는 참고용이다.
- 모르는 질문이 나오면 [8. 막혔을 때](#8-막혔을-때-쓰는-문장)의 문장을 쓴다. 지어내지 않는 것이 가장 안전하다.

## 1. 30초 소개 (이것만은 외워 가기)

> 서울시가 공개한 **생활인구 데이터**로 **두 행정동을 나란히 비교**하는 데스크톱 프로그램입니다.
> 수업에서 배운 **PyQt5**로 화면을 만들었고, 그래프는 **matplotlib**으로 그렸습니다.
> 사용법은 두 단계입니다. **‘데이터 불러오기’ 버튼으로 CSV 파일 두 개를 고르면** 30만 행이 넘는 데이터를 행정동별로 요약하고,
> 바로 **차트 화면**으로 넘어갑니다. 지역 A와 B를 고르면 **시간대·요일·성별·연령별 11가지 차트**를 같은 기준으로 비교해 줍니다.
> 결과는 PNG 그림과 CSV 표로 저장할 수 있고, 디자인은 헬로키티 색상으로 맞췄습니다.

**생활인구란?** 특정 시간에 그 지역에 **있던** 사람 수의 추정치다(서울시 + 통신사 데이터). 주민등록 인구도, 방문자 수도 아니다. 예: 역삼1동은 사는 사람보다 낮에 일하러 온 사람이 훨씬 많다.

## 2. 단어 8개만 알고 가기

| 단어 | 쉬운 뜻 | 비유 |

| **위젯** | 화면의 부품 하나하나(버튼, 글자, 목록 상자, 그래프 영역) | 레고 블록 한 개 |
| **레이아웃** | 위젯을 가로·세로로 줄 세우는 규칙. 창 크기가 바뀌어도 자동 정렬된다 | 블록을 끼우는 판 |
| **시그널과 슬롯** | “버튼이 눌렸다(시그널)” → “이 함수를 실행해라(슬롯)”를 이어 주는 PyQt의 연결 방식 | 초인종과 문 열어 주는 사람 |

| **matplotlib** | 파이썬의 대표적인 그래프 그리기 도구 | 그래프 전용 도화지 |
| **CSV** | 쉼표로 칸을 나눈 표 형식의 텍스트 파일. 엑셀로 열린다 | 글자로 된 엑셀 표 |
| **캐시** | 한 번 계산한 결과를 저장해 두고 다음에 재사용하는 것 | 미리 만들어 둔 반찬 |

## 3. 프로그램은 파일 8개 — 식당에 비유하면

| 파일 | 하는 일 | 식당 비유 |
|---|---|---|
| `app.py` | 프로그램 시작점. 창을 띄울지, 글자로만 결과를 볼지 정한다 | 식당 문 열기 |
| `hotplace/dataset.py` | CSV를 읽고, 검사하고, 행정동별로 요약한다 | 재료 손질 |
| `hotplace/hotplace.py` | 14가지 분석을 계산한다 | 요리 |
| `hotplace/analytics.py` | 두 지역의 유사도 같은 비교 수치를 계산한다 | 세트 메뉴 구성 |
| `hotplace/plotting.py` | 계산 결과를 그래프로 그린다 | 접시에 담기 |
| `hotplace/widgets.py` | 지표 비교표, 차트 선택 상자, 차트 도구 모음 같은 화면 부품 | 식기와 테이블 |
| `hotplace/ui.py` | 부품을 조립해 전체 화면을 만들고, 버튼과 기능을 연결한다 | 홀 매니저 |
| `hotplace/theme.py` | 색상, 글꼴, 아이콘, 키티 그림 | 인테리어 |

> 핵심 설계는 **“계산”과 “화면”을 나눈 것**입니다.
> 계산하는 파일(dataset, hotplace, analytics)은 화면이 없어도 동작하고,
> 화면 파일(ui, widgets, plotting, theme)은 계산 결과를 받아서 보여 주기만 합니다.
> 그래서 디자인을 바꿔도 분석 수치는 달라지지 않습니다.

## 4. 시연 대본 (약 5분)

발표 전에 [9. 체크리스트](#9-발표-전-체크리스트)대로 한 번 실행해 두면 데이터가 1초 안에 열린다.

**① 실행 — 첫 화면**

```bash
cd studies/study1/seoul-population-kitty
uv run app.py
```

> 프로그램을 실행하면 안내 화면이 나옵니다. 메뉴나 설정 없이 “데이터 불러오기” 버튼 하나만 있습니다.
> 사용 순서를 파일 선택 → 지역 선택 → 분석, 세 단계로 안내합니다.

**② ‘데이터 불러오기’ 클릭 → 파일 선택 창에서 두 파일을 함께 선택** (⌘ 또는 Ctrl을 누른 채 `LOCAL_PEOPLE_DONG_201912.csv`와 `dong_code.csv` 클릭 → 열기)

> 버튼을 누르면 파일 선택 창이 열립니다. 생활인구 CSV와 행정동 코드표, 두 파일을 한 번에 고릅니다.
> 어느 파일이 생활인구 파일인지는 프로그램이 알아서 구분하기 때문에 고르는 순서는 상관없습니다.
> 2019년 12월 한 달, 서울 424개 행정동, 약 31만 5천 행입니다.
> 파일을 읽는 동안에도 창이 멈추지 않도록 **별도 스레드**에서 읽고, 진행률을 막대로 보여 줍니다.
> 한 번 읽은 결과는 저장해 두기 때문에 두 번째 실행부터는 바로 열립니다.

**③ 차트 화면 (자동으로 이동)**

> 불러오기가 끝나면 생활인구가 가장 많은 두 곳, 역삼1동과 여의동이 자동으로 선택됩니다.
> 왼쪽에는 지역 선택과 네 가지 지표를 A·B 두 칸으로 나란히 놓은 비교표, 오른쪽에는 비교 차트가 있습니다.
> 지역 A는 빨강, B는 파랑으로 끝까지 같은 색을 씁니다.

**④ 지역 B를 ‘마포구 → 서교동’(홍대)으로 변경**

> 자치구를 고르면 그 구의 행정동 목록만 나옵니다.
> 지역을 바꾸는 순간 지표와 차트가 함께 다시 계산됩니다.
> 역삼1동은 주말 인구가 평일의 0.70배인 **업무지구형**, 서교동은 1.07배인 **주말 상권형**으로 나옵니다.
> 가장 붐비는 시간도 역삼1동은 14시, 서교동은 18시입니다.

**⑤ 차트 읽기** (마우스로 위쪽 A 차트와 아래쪽 B 차트의 눈금을 가리키며)

> 위가 지역 A, 아래가 지역 B입니다. 가장 붐비는 시간에는 점과 값을 직접 적어 두었습니다.
> 두 차트는 세로축 눈금을 똑같이 맞춰서, 그래프 높이만 봐도 크기를 공정하게 비교할 수 있습니다.

**⑥ ‘분석 분류’와 ‘차트’ 바꾸기** — ‘하루 흐름 → 평일·주말’, ‘요일·날짜 → 요일별’, ‘성별·연령 → 남녀 비율’, ‘성별·연령 → 연령’(피라미드)

> 차트는 모두 11가지이고 세 묶음으로 나눴습니다.
> 요일별 차트에서는 역삼1동은 평일이, 서교동은 금·토요일이 높게 나옵니다.
> 남녀 비율 차트는 실선이 여성, 점선이 남성입니다. 서교동은 오후에 여성 비율이 58%까지 올라가고, 역삼1동은 하루 종일 남성이 조금 더 많습니다.
> 연령 차트는 왼쪽이 남자, 오른쪽이 여자인 피라미드이고 두 지역이 같은 눈금을 씁니다.

**⑦ ‘PNG 저장’ 또는 ‘CSV 저장’**

> 차트는 PNG 그림으로, 수치는 엑셀에서 열리는 CSV로 저장할 수 있습니다.

**⑧ 마무리**

> 정리하면, PyQt5로 화면을 만들고 matplotlib으로 그래프를 그렸으며,
> 계산과 화면을 분리해서 같은 데이터를 11가지 차트로 비교할 수 있게 했습니다.
> 자동 테스트 37개로 계산과 화면 동작을 검증했습니다. 감사합니다.

## 5. “이 기능은 어떻게 구현했어요?” — 질문별 답변

### Q1. 화면은 무엇으로 만들었나요? 왜 PyQt5인가요?

- **한 줄 답:** 수업에서 배운 PyQt5로 만들었습니다. 버튼·목록·창 같은 부품(위젯)을 코드로 조립했습니다.
- **풀어서 말하기:**
  > PyQt5는 파이썬으로 데스크톱 프로그램 화면을 만드는 라이브러리입니다.
  > 수업에서는 Qt Designer로 화면을 그렸지만, 이 프로그램은 화면이 복잡하고 데이터에 따라 내용이 바뀌어서
  > 위젯을 **코드로 직접 만들고 배치**했습니다. 버튼과 입력 상자의 세련된 모양은
  > PyQt5용 공개 디자인 라이브러리인 **PyQt-Fluent-Widgets**를 사용했습니다.
- **코드 위치:** `hotplace/ui.py › MainWindow._build_ui` (208줄 부근). 맨 위 `from PyQt5.QtWidgets import ...`가 수업 코드와 같은 형태다.
- **더 물어보면:** 처음에는 PySide6로 만들었다가 PyQt5로 옮겼다. 둘 다 같은 Qt를 파이썬에서 쓰게 해 주는 도구라 구조는 같고, 달라진 것은 ① `import` 이름, ② 시그널 선언이 `Signal` → `pyqtSignal`, `Slot` → `pyqtSlot`, ③ 고해상도 화면 설정을 직접 켜는 것 정도다. 옮긴 뒤 화면을 캡처해 비교했을 때 달라진 픽셀은 0.4% 미만(글자 가장자리)이었다.

### Q2. 버튼을 누르면 어떻게 기능이 실행되나요?

- **한 줄 답:** PyQt의 **시그널과 슬롯**으로 연결했습니다. “눌렸다”는 신호와 실행할 함수를 `connect`로 이어 줍니다.
- **풀어서 말하기:**
  > 초인종과 같습니다. 버튼은 눌리면 `clicked`라는 신호를 보내고,
  > 저는 그 신호에 “이 함수를 실행해 줘”라고 미리 연결해 둡니다.
  > 예를 들어 ‘PNG 저장’ 버튼은 `_save_png`라는 함수에 연결되어 있습니다.
- **코드 위치:** `hotplace/ui.py › _build_chart_panel`
  ```python
  self.save_png_button.clicked.connect(self._save_png)
  ```
- **더 물어보면:** 버튼뿐 아니라 목록 선택(`currentIndexChanged`), 글자 입력(`textChanged`)도 같은 방식이다. 내가 만든 부품도 신호를 보낼 수 있다. 예: 지역 선택 상자는 `changed = pyqtSignal()`을 선언해 두고, 지역이 바뀌면 `self.changed.emit()`으로 알린다.

### Q3. 데이터를 불러오면 화면이 어떻게 차트로 바뀌나요?

- **한 줄 답:** 화면 두 장을 겹쳐 두고 한 장만 보여 주는 `QStackedWidget`을 썼습니다.
- **풀어서 말하기:**
  > 카드 두 장을 포개 놓고 맨 위 카드만 바꾸는 방식입니다.
  > 0번은 ‘데이터 불러오기’ 안내 화면, 1번은 차트 화면입니다.
  > 불러오기가 끝나면 보여 줄 번호를 1로 바꾸기만 하면 됩니다.
  > 초보자도 바로 쓸 수 있도록 메뉴나 설정 화면 없이 이 두 장만 두었습니다.
- **코드 위치:** `hotplace/ui.py › _build_ui`(화면 두 장 만들기), `_on_loaded`(468줄 부근, 차트 화면으로 전환)
  ```python
  self.pages = QStackedWidget()                  # 0: 데이터 불러오기, 1: 차트 보기
  self.pages.setCurrentIndex(1)                  # 차트 보기로 넘어간다
  ```
- **더 물어보면:** 차트 화면 오른쪽 위의 ‘다른 데이터 불러오기’ 버튼은 첫 화면의 버튼과 같은 함수(`load_data`)에 연결되어 있다. 다시 불러오는 동안에는 0번 화면으로 돌아가 진행 막대를 보여 준다.

### Q4. 화면 전환 애니메이션은 왜 없나요?

- **한 줄 답:** 분석 도구라서 **즉시 반응**하는 쪽을 택했습니다. 기본 `QStackedWidget`으로 바로 전환합니다.
- **풀어서 말하기:**
  > 이전 버전에는 화면이 미끄러지며 바뀌는 효과가 있었는데,
  > 차트를 빠르게 넘겨 보며 비교할 때는 오히려 방해가 되고 코드도 복잡해져서 뺐습니다.
  > 디자인 라이브러리에 들어 있던 부드러운 스크롤, 목록이 펼쳐지는 효과, 알림이 미끄러져 들어오는 효과도 껐습니다.
- **코드 위치:** `hotplace/ui.py › _scroll_page`(스크롤), `_notify`(알림), `hotplace/widgets.py › ComboBox`(목록)
- **더 물어보면:** 스크롤은 `setSmoothMode(SmoothMode.NO_SMOOTH, ...)`, 진행 막대는 `ProgressBar(useAni=False)`로 껐다. 테스트 `test_screens_switch_immediately_without_animation`이 실행 중인 애니메이션이 하나도 없는지 확인한다.

### Q5. 파일 두 개는 어떻게 고르나요? 어느 쪽이 생활인구 파일인지는 어떻게 아나요?

- **한 줄 답:** PyQt의 파일 선택 창(`QFileDialog`)에서 두 파일을 한 번에 고르고, **첫 줄의 칸 수**로 종류를 구분합니다. 파일 선택 창은 다른 창에 가려지지 않게 **항상 맨 앞** 옵션을 켰습니다.
- **풀어서 말하기:**
  > ‘데이터 불러오기’ 버튼을 누르면 여러 파일을 고를 수 있는 파일 선택 창이 열립니다.
  > 고른 파일마다 첫 줄, 즉 제목 줄만 읽어 봅니다.
  > 생활인구 파일은 날짜·시간·코드·총인구에 남녀 연령대 28칸이 붙어 **32칸 이상**이고, 행정동 코드표는 **5칸**입니다.
  > 그래서 32칸 이상이면 생활인구 파일, 아니면 코드표로 판단합니다. 파일 이름이나 고른 순서는 상관없습니다.
  > 하나만 골랐으면 나머지 파일을 고르는 창을 한 번 더 띄웁니다.
- **코드 위치:** `hotplace/ui.py › load_data`, `_pick_files`(353줄 부근), `_file_dialog`(390줄 부근) → `hotplace/dataset.py › identify_csv`(404줄 부근)
  ```python
  dialog = QFileDialog(self, caption, self._last_dir, CSV_FILTER)
  dialog.setOption(QFileDialog.DontUseNativeDialog, True)      # Qt 가 직접 그리는 파일 창
  dialog.setWindowFlag(Qt.WindowStaysOnTopHint, True)          # 항상 맨 앞
  dialog.setFileMode(QFileDialog.ExistingFiles)                # 여러 파일 선택
  return "population" if len(header) >= COL_END else "codes"      # COL_END = 32
  ```
- **더 물어보면:** 세 개 이상 고르거나 같은 종류를 두 개 고르면 경고 창을 띄우고 불러오지 않는다. 파일 선택 창은 기본 데이터 폴더에서 열리고, 그 뒤에는 마지막으로 고른 폴더를 기억한다(`_last_dir`).
- **“왜 윈도우/맥 기본 파일 창이 아닌가요?”라고 물으면:** 운영체제의 기본 파일 창에는 ‘항상 맨 앞’ 옵션을 줄 수 없어서, 그 옵션이 통하는 Qt 자체 파일 창을 썼다. 대신 왼쪽에 홈·바탕화면·문서·다운로드 바로가기를 넣었고(`setSidebarUrls`), 창의 글자는 Qt에 들어 있는 한국어 번역(`qtbase_ko`)을 불러와 한글로 나온다 — `hotplace/ui.py › run`. 참고로 macOS는 **다른 앱**을 클릭하면 그 앱의 창이 앞으로 오는 것이 운영체제의 규칙이라, 우리 앱으로 돌아오면 파일 창이 다시 맨 앞에 온다. Windows에서는 다른 앱 위에서도 계속 맨 앞에 있다.

### Q6. 데이터는 어떻게 불러오나요?

- **한 줄 답:** 파이썬 기본 기능인 `csv` 모듈로 **한 줄씩 읽으면서 바로 행정동별로 합산**합니다.
- **풀어서 말하기:**
  > 파일은 약 31만 5천 행입니다(424개 동 × 31일 × 24시간).
  > 전부 메모리에 올려 두지 않고, 한 줄 읽을 때마다 “이 동의 이 시간대 합계”에 더해 나갑니다.
  > 영수증 30만 장을 보관하는 대신 가게별 장부에 바로 적는 것과 같습니다.
  > 다 읽고 나면 동마다 24시간 합계, 평일·주말 합계, 성별·연령대 합계가 남고, 분석은 이 요약만으로 합니다.
- **코드 위치:** `hotplace/dataset.py › load_population` (236줄 부근), 요약 구조는 `DongAggregate`
- **더 물어보면:** 평균을 낼 때는 “합계 ÷ 실제로 관측된 횟수”로 나눈다. 데이터가 빠진 시간을 0명으로 치지 않기 위해서다. pandas를 쓰지 않은 이유는 [7. 꼬리 질문](#7-꼬리-질문-빠른-답) 참고.

### Q7. 불러오는 동안 창이 멈추지 않는 이유는요?

- **한 줄 답:** 파일 읽기를 **별도 스레드(`QThread`)**에서 하기 때문입니다.
- **풀어서 말하기:**
  > 식당에서 주방이 요리하는 동안 홀 직원은 계속 손님을 받는 것과 같습니다.
  > 파일 읽기는 뒤쪽 일꾼(스레드)에게 맡기고, 화면은 계속 움직입니다.
  > 일꾼은 “몇 퍼센트 했어요”, “다 했어요”, “실패했어요”를 **시그널**로 알려 주고,
  > 화면은 그 신호를 받아 진행 막대를 움직이거나 결과 화면으로 넘어갑니다.
- **코드 위치:** `hotplace/ui.py › LoadWorker`(84줄 부근)와 `start_load`(416줄 부근)
  ```python
  self._thread = QThread(self)
  self._worker = LoadWorker(population_csv, code_csv)
  self._worker.moveToThread(self._thread)
  self._thread.started.connect(self._worker.run)
  self._worker.progress.connect(self._on_progress)
  self._worker.loaded.connect(self._on_loaded)
  self._worker.failed.connect(self._on_failed)
  ```
- **더 물어보면:** 읽는 도중 창을 닫으면 `closeEvent`가 일꾼에게 중단을 요청하고(`requestInterruption`), 일꾼이 멈춘 것을 확인한 뒤 종료한다. 다시 불러오기가 실패해도 이전에 보던 분석 데이터는 그대로 남는다.

  > 그래서 앞의 500줄로 한 줄의 평균 길이를 재고, 파일 크기를 그 길이로 나눠 전체 줄 수를 어림합니다.
  > 2만 줄마다 진행률을 화면에 알립니다.

### Q9. 두 번째 실행부터 빨리 열리는 이유는요?

- **한 줄 답:** 요약 결과를 파일로 저장해 두는 **캐시**가 있어서입니다.
- **풀어서 말하기:**
  > 처음 읽을 때 만든 행정동별 요약을 `.cache` 폴더에 저장합니다.
  > 다음 실행에서는 CSV를 다시 읽지 않고 이 요약을 바로 불러옵니다.
  > 원본 파일의 경로·크기·수정 시각이 하나라도 바뀌면 다른 파일로 보고 처음부터 다시 읽습니다.
- **코드 위치:** `hotplace/dataset.py › _cache_path`와 `load_population` 앞부분
- **더 물어보면:** 저장 형식은 파이썬 기본 기능인 `pickle`이다. 캐시 파일이 깨져 있으면 지우고 다시 읽는다.

### Q10. 잘못된 파일을 넣으면 어떻게 되나요?

- **한 줄 답:** 읽으면서 **한 줄씩 검사**하고, 문제가 있으면 **몇 번째 줄이 왜 틀렸는지** 알림창으로 보여 줍니다.
- **풀어서 말하기:**
  > 날짜가 8자리 숫자인지, 시간이 0~23인지, 인구가 음수가 아닌지, 칸 수가 모자라지 않는지 확인합니다.

  > 파일을 고르는 단계에서도 걸러 냅니다. 같은 종류의 파일을 두 개 고르거나 세 개 이상 고르면 경고를 띄우고 불러오지 않습니다.

### Q14. 차트는 어떻게 고르게 했나요? 히트맵과 ‘서울 속 위치’는 왜 없나요?

- **풀어서 말하기:**
  > 차트 11개를 한 줄에 늘어놓으면 복잡해서 세 묶음(하루 흐름, 요일·날짜, 성별·연령)으로 나눴습니다.

  ```python

  ```
- **더 물어보면:** 차트 영역도 차트를 겹쳐 둔 `QStackedWidget`이고, 고른 한 장만 보여 준다. 차트는 **처음 볼 때만 계산**하고 결과를 기억해 둔다(`self._results`). 지역을 바꾸면 기억을 비우고 다시 계산한다 — `hotplace/ui.py › _render_current`. 꺼 둔 차트 번호는 목록에 없으므로 `AnalysisTabs.setCurrentIndex`가 무시한다.

### Q15. 그래프는 어떻게 PyQt 창 안에 들어가나요?

- **한 줄 답:** matplotlib이 제공하는 **PyQt용 그래프 위젯**(`FigureCanvasQTAgg`)을 화면에 끼워 넣었습니다.
- **풀어서 말하기:**
  > matplotlib은 보통 그래프를 별도 창으로 띄우지만, PyQt 화면 안에 넣을 수 있는 도화지 위젯도 제공합니다.
  > 그 위젯을 버튼이나 글자처럼 레이아웃에 배치하고, 분석 결과가 바뀔 때마다 도화지를 지우고 다시 그립니다.
- **코드 위치:** `hotplace/plotting.py › PlotCanvas`(도화지), `draw_result`(결과 종류에 맞는 그리기 함수 선택)
- **더 물어보면:** 계산 결과는 종류별 “결과 상자”에 담겨 온다 — 선 그래프용 `LineSeries`, 피라미드용 `AgePyramid`, 히트맵용 `Heatmap` 등. `draw_result`는 상자 종류를 보고 `draw_line_series`, `draw_age_pyramid`, `draw_heatmaps` 등을 부른다. 한글이 깨지지 않게 시작할 때 컴퓨터에 설치된 한글 글꼴을 찾아 지정한다(`configure_matplotlib`).

### Q16. 위아래 두 차트의 눈금이 같은 건 어떻게 했나요?

- **한 줄 답:** 그래프 두 칸을 만들 때 **축을 공유**하도록 옵션을 줬습니다.
- **풀어서 말하기:**
  > 눈금이 다르면 작은 지역의 그래프도 크게 보여서 잘못 비교하게 됩니다.
  > 그래서 A와 B가 가로축·세로축을 같이 쓰도록 했습니다. 한쪽을 확대하면 다른 쪽도 같이 확대됩니다.
- **코드 위치:** `hotplace/plotting.py › draw_paired_analysis`
  ```python
  axes = canvas.figure.subplots(2, 1, sharex=True, sharey=True)
  ```

### Q17. 차트에 마우스를 올리면 값이 나오나요? (지금은 꺼 둔 기능)

- **한 줄 답:** 그 기능은 **직접 만들어 두었지만 이 버전에서는 꺼 두었습니다.** matplotlib이 기본으로 주는 기능이 아닙니다.
- **풀어서 말하기:**
  > matplotlib이 기본으로 해 주는 것은 도구 모음에 마우스 위치의 x, y 좌표를 보여 주는 것뿐입니다.
  > 두 지역의 실제 값을 읽어 주는 기능은 제가 따로 만들었는데, 화면을 단순하게 하려고 이 버전에서는 스위치를 꺼 두었습니다.
  > 대신 가장 붐비는 시간의 값은 차트에 직접 적혀 있고, 정확한 수치가 필요하면 ‘CSV 저장’으로 표를 받을 수 있습니다.
- **켜는 방법:** `hotplace/plotting.py`의 `HOVER_ENABLED = False`를 `True`로 바꾸면 된다. 꺼져 있으면 마우스 이동 이벤트를 아예 연결하지 않는다.
- **“어떻게 만들었는데요?”라고 더 물으면:**
  > 그래프 위에서 마우스가 움직이면 matplotlib이 “지금 가로축 12.3 위치”라고 알려 줍니다.
  > 이를 반올림해 12시로 보고, 두 지역의 12시 값을 찾아 문장으로 만듭니다.
  > 그 문장을 시그널로 보내면 차트 아래의 글자 칸이 받아서 표시합니다. 세로 점선도 그 위치로 옮깁니다.
- **코드 위치:** `hotplace/plotting.py › PlotCanvas._on_hover`, `_series_readout` → `hotplace/widgets.py › AnalysisTab._show_readout`
  ```python
  hovered = pyqtSignal(str)                            # plotting.py: 신호 선언
  self.canvas.hovered.connect(self._show_readout)      # widgets.py: 글자 칸에 연결
  ```

### Q18. 차트 아래 확대·이동 버튼은 직접 만들었나요?

- **한 줄 답:** matplotlib의 기본 도구 모음을 가져와 **필요한 다섯 개만 남기고 한국어로** 바꿨습니다.
- **풀어서 말하기:**
  > 처음 범위, 뒤로, 앞으로, 이동, 확대 다섯 가지입니다. 아이콘은 앱 디자인에 맞는 것으로 바꿨습니다.
  > 저장 기능은 도구 모음에서 빼고 위쪽의 ‘PNG 저장’ 버튼으로 옮겼습니다.
- **코드 위치:** `hotplace/widgets.py › AnalysisToolbar` (112줄 부근)

### Q19. PNG·CSV 저장은 어떻게 하나요?

- **한 줄 답:** PNG는 matplotlib의 `savefig`, CSV는 파이썬 `csv` 모듈로 저장합니다. 저장 위치는 PyQt의 파일 대화상자(`QFileDialog`)로 고릅니다.
- **풀어서 말하기:**
  > PNG는 화면보다 선명하게(200dpi) 저장합니다.
  > CSV에는 두 지역 이름과 수치가 함께 들어갑니다. 엑셀에서 한글이 깨지지 않도록 `utf-8-sig` 형식으로 저장합니다.
- **코드 위치:** `hotplace/ui.py › _save_png`(701줄 부근), `_export_csv`(720줄 부근)
  ```python
  canvas.figure.savefig(path, dpi=200, facecolor=theme().surface)
  csv.writer(f).writerows(result.csv_rows())
  ```
- **더 물어보면:** 결과 상자마다 `csv_rows()`라는 “나를 표로 바꾸는 방법”이 들어 있어서, 저장 버튼은 차트 종류를 몰라도 된다.

### Q20. 헬로키티 디자인은 어떻게 입혔나요?

- **한 줄 답:** 색상 다섯 개를 한 곳에 정의하고, **Qt 스타일시트(QSS)**로 모든 위젯에 적용했습니다. 그림은 SVG 파일입니다.
- **풀어서 말하기:**
  > QSS는 웹의 CSS와 비슷합니다. “카드는 흰 배경에 둥근 모서리”, “제목은 굵게” 같은 규칙을 글로 적습니다.
  > 색은 헬로키티 팔레트의 빨강·노랑·흰색·파랑·갈색을 기준으로 했고, 그래프도 같은 색을 가져다 씁니다.
  > 그래서 색을 바꾸려면 `theme.py` 한 곳만 고치면 됩니다.
  > 버튼의 작은 아이콘은 그림 파일 없이 코드에 적은 선(SVG 경로)으로 그리고, 키티 얼굴은 SVG 파일을 불러옵니다.
- **코드 위치:** `hotplace/theme.py › KITTY_RED` 등(36줄 부근), `apply_theme`(132줄 부근), `make_icon`, `kitty_pixmap`
- **더 물어보면:** 위젯에 “역할 이름표”를 붙이고(`setProperty("role", "regionSelector")`), QSS에서 `QFrame[role="regionSelector"] { ... }`처럼 그 이름표에 스타일을 준다. 키티 SVG의 출처는 `hotplace/assets/README.md`에 적어 두었다.

### Q21. ‘상세 통계’ 창은요?

- **한 줄 답:** 버튼을 누르면 새 대화상자(`QDialog`)를 띄우고, 두 지역의 요약 문장을 글상자에 넣습니다.
- **코드 위치:** `hotplace/ui.py › _show_summary`(668줄 부근), 문장은 `hotplace/hotplace.py › summary_text`

### Q22. 제대로 동작하는지 어떻게 확인했나요?

- **한 줄 답:** **자동 테스트 37개**를 만들었고, 창 없이 결과만 확인하는 점검 모드도 있습니다.
- **풀어서 말하기:**
  > 답을 미리 아는 작은 가짜 데이터를 넣고 평균·비율이 맞게 나오는지,
  > A와 B를 바꿨을 때 결과가 정확히 뒤집히는지, 저장한 파일이 제대로 만들어지는지 확인합니다.
  > 파일 두 개를 어떤 순서로 골라도 올바르게 구분하는지, 잘못 고르면 불러오지 않는지도 테스트합니다.
  > 화면 테스트는 창을 띄우지 않는 모드에서 버튼 클릭을 흉내 냅니다.
- **코드 위치:** `tests/test_analytics.py`, `tests/test_comparison.py`
  ```bash
  uv run python -m unittest discover -s tests -v   # 테스트 37개
  uv run app.py --check 역삼1동                     # 창 없이 분석 1~13 점검
  ```
- **더 물어보면:** 실제 2019년 12월 데이터에서 역삼1동은 일평균 112,399명, 가장 붐비는 시간 14시, 낮÷밤 2.15배, 주말÷평일 0.70배가 나온다.

### Q23. 다른 컴퓨터에서도 실행되나요?

- **한 줄 답:** 네. `uv sync` 한 번이면 필요한 라이브러리가 설치되고, macOS용 앱 파일로 묶을 수도 있습니다.
- **코드 위치:** `pyproject.toml`(필요한 라이브러리 목록), `Hotplace.spec`(PyInstaller 앱 빌드 설정)

## 7. 꼬리 질문 빠른 답

| 질문 | 답 |
|---|---|
| PyQt5와 PySide6는 뭐가 다른가요? | 둘 다 같은 Qt를 파이썬에서 쓰게 해 주는 도구입니다. 만든 회사와 라이선스가 다르고 사용법은 거의 같습니다. 수업에 맞춰 PyQt5로 작성했습니다. |
| 왜 pandas를 안 썼나요? | 필요한 것이 “행정동별 합계”뿐이라 기본 `csv` 모듈로 한 줄씩 읽으며 더하는 편이 메모리를 적게 쓰고 설치할 것도 줄어듭니다. |
| Qt Designer(.ui 파일)는 안 썼나요? | 카드와 차트가 데이터에 따라 만들어지고 개수도 많아서(지표 표 4줄, 차트 13장) 반복문으로 코드에서 만드는 편이 간단했습니다. |
| 일평균 11만 명이면 하루에 11만 명이 방문했다는 뜻인가요? | 아닙니다. 어느 시간에 보든 평균 11만 명쯤 **있었다**는 뜻입니다. 같은 사람이 여러 시간대에 중복으로 세어집니다. |
| 메뉴나 설정 화면은 왜 없나요? | 처음 쓰는 사람도 헤매지 않도록 ‘데이터 불러오기 → 차트 보기’ 두 단계만 남겼습니다. 검색·리포트 화면은 원본 버전(`seoul-population`)에 있습니다. |
| 히트맵은 왜 뺐나요? | 색의 진하기로 값을 읽어야 해서 처음 보는 사람에게 어렵습니다. `DISABLED_CHARTS`에서 번호를 지우면 다시 나타납니다. |
| 남녀 비율의 두 선은 왜 거울처럼 대칭인가요? | 남성 비율 = 100 − 여성 비율이기 때문입니다. 선 하나만 있어도 같은 정보지만, 남녀를 모두 보여 주는 편이 읽기 쉬워서 둘 다 그렸습니다(`hotplace.py › analysis11`). |
| 공휴일은 따로 처리했나요? | 하지 않았습니다. 평일에 있는 공휴일(12월 25일)은 평일로 계산됩니다. 한계로 알고 있습니다. |
| 데이터에 빠진 시간이 있으면요? | 0명으로 채우지 않고 “관측 없음”으로 둡니다. 평균은 실제로 관측된 횟수로만 나눕니다. |
| 같은 지역을 A와 B에 넣으면요? | 동작합니다. “지역 A와 B가 같습니다”라는 안내가 뜹니다. |
| 다른 달 데이터도 되나요? | 같은 형식(`LOCAL_PEOPLE_DONG_YYYYMM.csv`)이면 됩니다. 차트 화면 오른쪽 위의 ‘다른 데이터 불러오기’로 파일만 다시 고르면 됩니다. |
| 가장 어려웠던 점은요? | ① 큰 파일을 읽는 동안 화면이 멈추지 않게 스레드로 분리한 것, ② 두 지역을 공정하게 비교하도록 축과 색 범위를 맞춘 것, ③ PySide6에서 PyQt5로 옮기면서 디자인이 달라지지 않게 검증한 것입니다. |
